# Распределение сделок — виджет для amoCRM

Автоматически назначает ответственного менеджера на входящие сделки по выбранной стратегии.

## Возможности

- **Стратегии распределения:**
  - **По очереди (round-robin)** — по кругу между менеджерами пула;
  - **По загрузке** — тому, у кого меньше открытых сделок;
  - **По правилам** — `источник / воронка / бюджет / тег → менеджер` (первое совпадение).
- **Пул менеджеров** — кто участвует в раздаче.
- **Область** — на какие воронки распространяется (пусто = все).
- **Пропуск отсутствующих** — не назначать тем, кто вне графика/оффлайн.
- **SLA-переназначение** — если менеджер не взял сделку за N минут, передать следующему.
- **Панель в карточке сделки** — кому и почему назначена, кнопка «Переназначить».

## Структура

```
deal_distribution/
├── manifest.json               # locations: lcard-1, settings, advanced_settings; oauth Y
├── script.js                   # карточка + страница правил + сохранение
├── i18n/{ru,en}.json           # локализация (паритет ключей)
├── images/                     # 6 PNG точных размеров (плейсхолдеры, teal)
├── templates/
│   └── advanced_settings.twig  # страница «Правила распределения»
├── scripts/make_logos.py       # генератор иконок (без зависимостей)
└── docs/spec.md                # контракт и алгоритмы backend
```

## Настройки виджета (в amoCRM)

- **URL backend виджета (https)** — адрес сервера;
- **Ключ доступа к backend** (`api_token`) — совпадает с `API_SECURITY_KEY` на сервере
  (уходит в заголовке `X-Security-Key`).

Правила распределения — на отдельной странице **«Правила распределения»** (advanced settings).

## Сборка архива

```bash
cd deal_distribution
zip -r -X ../deal-distribution-widget.zip \
    manifest.json script.js i18n images templates \
    -x '*.DS_Store' -x '__MACOSX*'
# manifest.json должен быть в КОРНE архива
```
Иконки при необходимости пересобрать: `python3 scripts/make_logos.py`.

## Backend

Фронтенд готов и валиден; серверная часть описана в [`docs/spec.md`](docs/spec.md)
(эндпойнты, алгоритмы стратегий, безопасность вебхуков, модель данных). Реализуется
на том же каркасе NestJS + OAuth amoCRM + Postgres, что и соседние виджеты.

> Иконки — плейсхолдеры (бренд-цвет KO:AGENCY). Заменить на финальный дизайн перед публикацией.
