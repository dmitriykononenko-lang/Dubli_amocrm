# Поиск и объединение дублей — виджет для amoCRM

Виджет находит и объединяет дубликаты **контактов, компаний и сделок** в amoCRM:
гибкие правила поиска (комбинации полей по И/ИЛИ), нормализация значений
(телефоны, email, имена), проверка дублей при работе в карточке и запрет на
создание новых дублей.

> **Статус: фронт-каркас (Этап 2) + ядро бэкенда (Этап 3, в работе).**
> Фронтенд-виджет проходит валидацию амоМаркета (плашка-заглушка в карточке и
> статический скелет настроек). Серверное ядро в `backend/` уже реализует OAuth с
> amoCRM, шифрованное хранение токенов, API-клиент v4, приём вебхуков с проверкой
> `security_key` и идемпотентностью, нормализацию ключей, индексацию в `entity_keys`
> и поиск дублей для плашки (`GET /api/duplicates`) с учётом правил AND/OR.
> **Объединение дублей и фоновое сканирование — следующий слой.**

## Что уже есть (Этап 2)

- Манифест с `oauth: "Y"` (виджет работает с API amoCRM от имени аккаунта),
  локациями карточек и настроек, служебными полями `backend_url` и
  `security_key`.
- Плашка в карточке сделки/контакта/компании: заголовок «Проверка дублей»,
  состояние «дублей не найдено», неактивные кнопки **«Открыть»** и
  **«Объединить»**. Реальной проверки нет — `checkDuplicates()` это заглушка.
- Статический скелет настроек с секциями: **Сущности** (контакты/компании/
  сделки), **Правила поиска (AND/OR)**, **Нормализация**, **Права на
  объединение**, **Запрет создания дублей**.
- Локализация: русский и английский.
- Набор логотипов KO:AGENCY (тема «дубли/слияние»).
- Локальный тестовый стенд (Node + JSDOM + jQuery).

## Сборка архива

Файлы виджета должны лежать в **корне** архива (`manifest.json` на верхнем уровне):

```bash
cd widget && zip -r ../dubli-widget.zip . && cd ..
```

## Установка

1. Сгенерируйте логотипы (если папка `widget/images/` пуста):

   ```bash
   python3 scripts/make_logos.py   # при необходимости: pip install Pillow
   ```

2. Соберите архив (см. выше).
3. В amoCRM откройте **амоМаркет → Разработчикам → Создать интеграцию**
   (приватная интеграция). Так как у виджета `oauth: "Y"`, в настройках
   интеграции укажите **ссылку для перенаправления (redirect_uri)** и
   получите **секретный ключ** — они понадобятся серверной части на Этапе 3.
4. На вкладке виджета загрузите `dubli-widget.zip` и установите интеграцию в
   аккаунт.

> На Этапе 2 поля `backend_url` и `security_key` в настройках — заглушки;
> бэкенд (OAuth-сервер, вебхуки, индекс дублей, объединение) появится на
> следующем этапе.

## Тесты

```bash
node test/run-tests.js
```

Проверяется: рендер плашки в lcard/ccard/comcard, определение сущности по
`area` и по URL, совпадение структуры ключей `ru.json`/`en.json`, очистка
DOM и слушателей в `destroy()`. Код выхода `0` — все проверки пройдены.

## Бэкенд (Этап 3)

Серверное ядро — в `backend/` (NestJS, PostgreSQL через Kysely). Запуск, переменные
окружения и тесты описаны в `backend/README.md`.

**Готово (ядро):** OAuth-флоу (`GET /oauth/callback`), шифрованное хранение токенов
(AES-256-GCM, ключ за интерфейсом KMS) с авто-refresh, API-клиент amoCRM v4
(троттлинг ~7 rps, ретраи), приём вебхуков (`POST /webhooks/amo`) с проверкой
`security_key` и идемпотентностью, нормализация ключей (телефон/email/ИНН/имя →
SHA-256) и индексация в `entity_keys`, поиск дублей `GET /api/duplicates` для плашки
(по общим ключам, с учётом правил AND/OR). Health-эндпоинт `GET /health`.

**Осталось:** объединение дублей (журнал + снапшоты + откат), фоновое сканирование
(`scan_jobs`); на фронте — реальная `checkDuplicates()` (запрос к `GET /api/duplicates`),
активные кнопки «Открыть»/«Объединить», рабочие настройки (CRUD правил AND/OR, права,
запрет создания дублей).
