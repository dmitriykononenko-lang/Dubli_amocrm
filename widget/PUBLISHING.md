# Публикация виджета «Дубли» в amoCRM

Пошагово: от создания интеграции в кабинете до загрузки архива и (по желанию)
подачи в маркетплейс. Секреты (`secret_key`, токены, ключи) в git не коммитим —
`code` и `secret_key` подставляются в архив при сборке из `widget/.publish.env`.

## 0. Что уже готово

- `manifest.json` — `interface_version: 2`, `oauth: "Y"`, `installation: true`,
  локации `settings` + `advanced_settings`, поля установки `phone` (обяз.) и
  `security_key` (обяз.). `code`/`secret_key` пустые — подставит `package.sh`.
- `i18n/ru.json`, `i18n/en.json` — все строки вынесены, ru/en в паритете
  (проверка: `python3 scripts/i18n_diff.py widget` из корня скила виджетов).
- `images/` — `logo.png` 90×90, `logo_small.png` 30×30, `logo_dp.png` 174×109,
  плюс маркетинговые `logo_main.png` / `logo_medium.png` (фирменные цвета
  KO:AGENCY: off-black `#141414`, красный `#d22730`).
- Бэкенд с OAuth 2.0, вебхуками и API — на `https://dubli.koagency.ru`.

## 1. Создать интеграцию в кабинете разработчика

1. `https://www.amocrm.ru/developers` → войти аккаунтом-владельцем виджета.
2. **Создать интеграцию** → «Виджет».
3. Заполнить: название, описания (можно взять из `i18n/ru.json` → `widget.*`),
   контакты поддержки.
4. **OAuth 2.0**:
   - Ссылка для перенаправления (redirect URI) — **точно** как в бэкенде
     (`AMOCRM_REDIRECT_URI`): `https://dubli.koagency.ru/oauth/callback`
     (протокол, хвостовой слэш, порт — всё должно совпадать до символа).
   - Права доступа: выдать доступ к **CRM** (чтение/запись контактов, компаний,
     сделок, примечаний и задач) — виджету это нужно для поиска/объединения
     дублей и ведения сделок.
5. Сохранить. Кабинет выдаст **Код интеграции** (`code`) и **Секретный ключ**
   (`secret_key`) — вкладка «Ключи и доступы». `code` после создания не меняется.

## 2. Прописать секреты для сборки

```bash
cp widget/.publish.env.example widget/.publish.env
# впишите WIDGET_CODE и WIDGET_SECRET_KEY из кабинета
```

`widget/.publish.env` в git не попадёт (см. `.gitignore`).

## 3. Собрать архив

```bash
./widget/package.sh          # → widget/dubli-<version>.zip
```

Скрипт подставит `code`+`secret_key` в `manifest.json` **внутри архива**
(в репозитории манифест остаётся без секрета), проверит обязательные поля и
упакует так, что `manifest.json` лежит в КОРНЕ архива (частая ошибка — лишняя
вложенная папка).

Проверить содержимое: `unzip -l widget/dubli-<version>.zip` — должны быть
`manifest.json`, `script.js`, `i18n/…`, `images/…` без префикса `widget/`.

## 4. Загрузить

Кабинет → ваша интеграция → **Загрузить виджет** → выбрать zip. Кабинет
проверит манифест и подпишет архив. Статус → «загружен».

- **Приватно** (для своих аккаунтов) — уже можно устанавливать по коду интеграции.
- **В маркетплейс** — нажать «Отправить на модерацию» (см. чек-лист ниже).

## 5. Версии

`widget/manifest.json` → `widget.version` (semver) **бумпать на каждую загрузку**
— кабинет отклонит версию ≤ уже загруженной.
- patch (`1.1.6`→`1.1.7`) — фикс; minor — новая функция; major — ломающее
  изменение (схема манифеста/настроек).

Рекомендация: бумп версии — в том же коммите, что и правка; тег `git tag v1.1.7`;
собирать из тега — тогда «что в проде» всегда однозначно.

## 6. Чек-лист перед подачей в маркетплейс

Модерация чаще всего заворачивает за это — пройдите до отправки:

- [ ] **Нет хардкод-строк** — всё видимое из `i18n` (ru+en в паритете).
- [ ] **Описание = реальность** — не обещать того, чего виджет не делает
      (модератор ставит и проверяет).
- [ ] **Поддержка живая** — `support.link` открывается, email не отбивает.
- [ ] **Нет ошибок в консоли** при установке/рендере/`init`.
- [ ] **Чистое удаление** — после снятия виджета не остаётся артефактов/таймеров.
- [ ] **OAuth**: redirect URI в кабинете == URL бэкенда; токены обновляются
      (refresh), хранятся шифрованно.
- [ ] **Права не с запасом** — просить только реально нужный доступ (CRM).
- [ ] **Скриншоты 1280×800** — снять на рабочем аккаунте (вкладки «Настройки
      виджета», «Массовая очистка», «Автоматическая очистка», «Оплата»).
- [ ] **Категория/страны/`free`** — заполнить в карточке маркетплейса (виджет
      платный: подписка за пользователя; онлайн-оплата — ЮKassa).

## 7. Обновление уже установленного виджета

- patch/minor — тихое обновление, пользователь видит новое поведение при
  следующей загрузке страницы.
- major — amoCRM не переустанавливает автоматически; предусмотреть в `init`
  совместимость со старой формой настроек хотя бы один релиз.
