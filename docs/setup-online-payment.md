# Инструкция: подключение онлайн-оплаты (ЮKassa) для виджета «Дубли»

Эта инструкция — для агента/деплой-инженера. Код на бэкенде уже готов
(создание платежа, ссылка на оплату, вебхук, продление подписки, перевод сделки
на этап «Оплачен»). Нужно завести магазин ЮKassa, прописать ключи в `.env`,
настроить вебхук и передеплоить. Ничего программировать не требуется.

## Что уже работает в коде

- Виджет, вкладка «Оплата» → кнопка **«Оплатить онлайн»** шлёт
  `POST /api/billing/checkout` → бэкенд создаёт платёж в ЮKassa и возвращает
  ссылку на hosted-страницу оплаты (SberPay / карта / ЮMoney / СБП).
- **Вебхук** `POST /api/billing/yookassa/webhook` — ЮKassa уведомляет об оплате.
  Тело не доверяем: платёж перепроверяется по id через API ЮKassa. При успехе:
  - продлевается подписка клиента (`paid_until`);
  - сделка клиента в нашей amoCRM двигается на этап **«Оплачен»** + примечание.
- Кнопка **«Запросить счёт»** (безнал) уже работает отдельно — создаёт/двигает
  сделку клиента на этап «Запрошен счёт» и ставит задачу менеджеру.

## Шаг 1. Завести магазин ЮKassa

1. Зарегистрировать магазин на https://yookassa.ru (нужно юрлицо или ИП + договор).
2. В личном кабинете ЮKassa открыть **Интеграция → Ключи API**.
3. Скопировать:
   - **shopId** (идентификатор магазина, число);
   - **секретный ключ** (`live_...` для боевого режима или `test_...` для теста).

## Шаг 2. Прописать ключи в `.env` на сервере

В `.env` рядом с бэкендом `dubli` добавить/заполнить:

```dotenv
YOOKASSA_SHOP_ID=<shopId из ЮKassa>               # напр. 1175639
YOOKASSA_SECRET_KEY=<секретный ключ из ЮKassa>
BILLING_RETURN_URL=https://dubli.koagency.ru      # куда вернуть после оплаты

# Фискализация (54-ФЗ). Магазин с онлайн-кассой → true (иначе ЮKassa вернёт 400
# «Receipt is missing»). Email покупателя вводится на вкладке «Оплата».
YOOKASSA_FISCAL=true
YOOKASSA_VAT_CODE=1                                # 1 = без НДС (УСН). Подтвердить у владельца!

# для перевода сделки клиента на «Оплачен» в нашей amoCRM:
VENDOR_AMOCRM_SUBDOMAIN=koagency.amocrm.ru
VENDOR_AMOCRM_PIPELINE_ID=11130042                # воронка «Новые виджеты»

# тариф (необязательно — по умолчанию 399 / минимум 5):
BILLING_PRICE_PER_USER=399
BILLING_MIN_USERS=5
```

Секреты держать только в `.env` (в git не коммитить). Все переменные из `.env`
пробрасываются в контейнер backend автоматически (`env_file` в docker-compose.yml).

## Шаг 3. Настроить вебхук в ЮKassa

В кабинете ЮKassa: **Интеграция → HTTP-уведомления** →
- URL: `https://dubli.koagency.ru/api/billing/yookassa/webhook`
- События: как минимум **`payment.succeeded`** (можно добавить `payment.canceled`).

## Шаг 4. Передеплоить бэкенд

На сервере, в каталоге проекта `dubli`:

```bash
git fetch origin && git checkout claude/stoic-mccarthy-qdn9e7 && git pull
docker compose up -d --build
docker compose logs -f backend   # убедиться, что стартовал без ошибок
```

(`.env` подхватывается docker-compose автоматически.)

## Шаг 5. Проверка

1. Открыть виджет → вкладка **«Оплата»** → выбрать число пользователей и срок →
   **«Оплатить онлайн»** → должно перекинуть на страницу ЮKassa.
2. В **тестовом** режиме (ключ `test_...`) оплатить тестовой картой ЮKassa.
3. После оплаты ЮKassa вызовет вебхук. Проверить в логах бэкенда строку
   `Оплата подтверждена: аккаунт ... +N мес`.
4. В нашей amoCRM (`koagency.amocrm.ru`, воронка «Новые виджеты») сделка клиента
   должна переехать на этап **«Оплачен»** с примечанием.

Когда тест прошёл — заменить `test_...` ключ на боевой `live_...` в `.env` и
передеплоить (Шаг 4).

## Заметки

- **54-ФЗ / чеки.** Если нужна фискализация (онлайн-касса), в ЮKassa включается
  отдельно; в запрос платежа тогда добавляется объект `receipt` (позиции чека).
  Сейчас чек не формируется — сказать, если нужно, добавлю.
- **Безопасность.** Карточные данные через нас не проходят (hosted-оплата ЮKassa).
  Вебхук не доверяет телу — платёж перепроверяется по API. Дополнительно можно
  ограничить вебхук по списку IP ЮKassa на nginx.

  этапы («установлен» / «запрошен счёт» / «оплачен») бэкенд находит по названию.
