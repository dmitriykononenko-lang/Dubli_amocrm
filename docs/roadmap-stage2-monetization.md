# Этап 2 — монетизация, права, пользователи, лендинг

План по функционалу «как у F5/Rubikon». Составлен по присланным примерам
(cmdf5.ru/widjety-amocrm/poisk-dubley, ЮKassa-оплата, матрица прав, вкладки
Настройки/Пользователи/Оплата, объединение из карточки).

Стиль интерфейса — фирменный Ko:agency (красный акцент), как в Этапе 1.

## Фаза A. Оплата / биллинг (вкладка «Оплата»)

**UI виджета (вкладка «Оплата»):**
- Тариф: N ₽ за пользователя amoCRM в месяц, минимум M пользователей.
- Выбор срока (напр. 6 / 12 мес), «+ бонусные месяцы», расчёт суммы.
- Статус: «Оплачено до ДД.ММ.ГГГГ для K пользователей» / демо-режим.
- Кнопки: **«Оплатить онлайн»** и **«Запросить счёт»**.

**«Оплатить онлайн» → ЮKassa (hosted checkout):**
1. Виджет → бэкенд `POST /api/billing/checkout` (accountId, срок, число польз.).
2. Бэкенд считает сумму, создаёт платёж через ЮKassa Create Payment API
   (idempotence key), получает `confirmation.confirmation_url`.
3. Виджет редиректит на этот URL → страница ЮKassa (SberPay/карта/ЮMoney/СБП).
4. ЮKassa шлёт webhook `POST /api/billing/yookassa/webhook` → проверка подписи/IP →
   при `payment.succeeded` продлеваем `account.paid_until`, фиксируем оплату.
- Карточные данные бэкенд НЕ трогает. shopId/секрет — только в `.env` на сервере.

**Ведение клиента в НАШЕЙ amoCRM (Ko:agency) по этапам** — одна сделка на клиента,
её id храним в настройках клиентского аккаунта (`vendor_lead_id`), токены vendor-аккаунта
уже есть (виджет установлен в аккаунте Ko:agency):
1. **Установил виджет** — при OAuth-установке (`onClientInstalled`) заводим сделку
   «Дубли: {субдомен клиента}» на этапе «Установил» + примечание. Best-effort:
   сбой в нашей amoCRM не ломает установку у клиента.
2. **Запросил счёт** — `POST /api/billing/invoice-request` двигает сделку клиента на
   этап «Запросил оплату», пишет сумму примечанием, ставит задачу менеджеру.
3. **Оплатил** — (webhook ЮKassa) этап «Оплачен», бюджет = сумма.

Выделенная воронка и её этапы задаются в `.env` (`VENDOR_AMOCRM_PIPELINE_ID`,
`VENDOR_AMOCRM_STATUS_INSTALLED/REQUESTED/PAID`); без них — главная воронка,
без переходов, но с примечаниями/задачами.

**Ограничение доступа (entitlement):**
- `account.paid_until` + число оплаченных пользователей.
- Демо-режим до оплаты: лимит (напр. ≤3 объединений), как у F5.
- Проверка на бэкенде в `/api/merge` и др. (не только на фронте).

## Фаза B. Права и пользователи (вкладки «Пользователи» / «Права»)

- Матрица прав per-user × действие: сохранение дублей / ручной поиск /
  ручное объединение (список) / ручное объединение (в карточке).
- Значения: Запрещено / Если ответственный / Разрешено (по умолчанию — всем).
- Список пользователей amoCRM: `AMOCRM.constant('managers')` (+ отделы/группы).
- Бэкенд: таблица прав, endpoint GET/PUT, применение при проверке действий.

## Фаза C. Карточки (опционально — по решению)

- Плашка «Дубль»/«Антидубль» в карточке контакта/компании/сделки.
- Объединение из карточки и из списков (до 5 сущностей), цвет кнопки = доступность.
- Прикрепление дубля скрепкой, если сущность ещё не привязана.
- Требует вернуть локации `lcard/ccard/comcard` в манифест (код плашки уже написан).

## Фаза D. Лендинг (маркетинговая страница) — верстается отдельно

- Секции по примерам: описание, «Особенности работы виджета» (объединение из
  карточки, прикрепление, авто-очистка, настройка прав), тарифы, отзывы, FAQ,
  поддержка/инструкция/мессенджер. Фирменный стиль Ko:agency.

## Открытые решения (нужны от заказчика)

1. **Провайдер онлайн-оплаты:** ЮKassa (эквайринг; SberPay/карта/СБП/ЮMoney; нужен
   магазин ЮKassa на юрлицо/ИП) — рекомендуется, совпадает со скринами. Либо
   YooMoney-кошелёк (проще, но без SberPay/СБП).
2. **Тариф:** цена за пользователя/мес, минимум пользователей, сроки, бонусы/скидки.
3. **«Запросить счёт»:** аккаунт amoCRM для сделок (Ko:agency?), воронка и этап.
4. **Карточки:** возвращаем объединение в карточках (матрица прав это подразумевает)
   или остаёмся «только настройки».
5. **Юр. часть:** оферта/условия сервиса (ссылка), реквизиты для чеков.

## Секреты (только в `.env` на сервере, НЕ в гит и НЕ в чат)

- `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`
- `VENDOR_AMOCRM_*` (client_id/secret/redirect/subdomain, pipeline_id, status_id)
- webhook-секрет для проверки уведомлений ЮKassa
